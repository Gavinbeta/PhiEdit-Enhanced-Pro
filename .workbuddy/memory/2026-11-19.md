### 踩坑记录（重要，后续务必沿用）

1. **XAML 文件必须带 UTF-8 BOM**。XamlCompiler 按系统 ANSI 代码页读取，缺 BOM 时中文内容会导致 pass1 静默失败。
2. **控制台代码页必须是 UTF-8（`chcp 65001`）**，否则 XamlCompiler 报错时只输出 `MSB3073 ... 退出代码 1`，看不到任何诊断信息。仓库已提供 `build.cmd` / `run.cmd` 自动处理。
3. **WinUI 3 没有 `GridSplitter`**（UWP 独有），引用它会让 XAML 编译器崩溃。已自研 `Controls/ThinSplitter.cs`。
4. `CanvasControl` 是密封类，不能继承 → 改为 `UserControl` 内嵌 `CanvasControl` 的组合方式；`Invalidate()` 要转调 `_canvas.Invalidate()`。
5. Win2D 1.4 文本枚举是 `CanvasHorizontalAlignment` / `CanvasVerticalAlignment`（不是 `CanvasTextAlignment`）。
6. `Windows.UI.Colors` 不存在，用 `Microsoft.UI.Colors`；`System.Drawing.Color` 与 `Windows.UI.Color` 同名会二义，需别名。
7. `Slider.ValueChanged` 的事件参数类型在 WinUI 3 里没有 `RangeBaseValueChangedEventArgs`，改用 lambda 推断类型。
8. `FileSavePicker.FileTypeChoices` 是 `KeyValuePair<string, IList<string>>` 列表，不是 `FileTypeFilter`。
9. `DispatcherQueue.GetForCurrentThread()` 被 `Window.DispatcherQueue` 实例属性遮蔽，需写全限定名。

## 第二轮：按用户反馈修正时间轴方向与交互（提交 665b248）

用户对照原版 RPE 截图提出 5 点，已全部实现并实测验证：

1. **左右两区始终同步滚动** —— 根因是滚轮事件只让「收到事件的那一侧」重绘。现改为
   两侧共用 `EditorSession.Viewport`，任一侧滚动后触发 `ViewChanged` → 主窗口同时 `Invalidate()` 两个画布。
2. **拍号不能小于 0** —— 锚点 `AnchorBeat` 钳制 ≥0，且网格只画在判定线以上，判定线以下的窄带不画拍号。
3. **滚动方向改为从上到下** —— 关键认知：**原版 RPE 的时间轴自下而上流逝**（参考图实测拍号 5 在上、4 在下）。
   `EditViewport` 已重构为「锚点拍 + 判定线固定底部」模型：`YAtBeat(b) = PlayheadY - (b - Anchor) * k`。
4. **判定线固定在两区最下方** —— 粗灰线画在 `PlayheadY`（画布底部 -26px 窄带），
   网格（整拍线/黄横线/黄竖线/轨道分隔竖线）全部裁剪到其上方，横线在判定线处断开；
   音符不受裁剪限制，绘制到离开可视区为止。判定线最后绘制压在最上层。
5. **点击选中不再误触发拖动** —— 位移超过 3px 才判定为拖动（两个编辑区都加了阈值）。

补充：播放头 / 视口锚点 / 底部进度条三者状态已统一（滚动等同于定位播放头）。

### 新增踩坑

- **构建产物路径不一致**：按解决方案构建输出到 `bin/x64/Debug/...`，按项目构建输出到 `bin/Debug/...`，

## 第三轮：纵向位置改为单一真源（提交 7e87688）

用户反馈：拖动底部进度条后编辑器不滚动，且只有点某个区才刷新，之后两侧不同步。
用户给出的思路：**不再直接操作编辑区竖直位置，改用一个独立变量，两区纵向位置都读它，
所有控制纵向位置的入口只改这个变量。** 已按此实现：

- `EditViewport.AnchorBeat` → `EditViewport.Position`（setter 私有、恒 >= 0），成为唯一真源；
  唯一修改入口：`SetPosition` / `ScrollByPixels` / `ScrollToBeat` / `ZoomAt`。
- 视口广播 `ViewChanged`；`NoteSurface` / `EventSurface` 在 `Session` setter 中订阅并立即重绘；
  主窗口订阅同一事件同步播放头、底栏读数与进度条。
- `RefreshTimeline()` 改为纯显示刷新，去掉「回写位置」造成的回环（这是之前两侧不同步的根因之一）。
- 缩放（Ctrl+滚轮）改为保持光标处的拍不动。

### 经验

- 界面里「多个控件影响同一状态」时，先把状态收敛到单一真源，再让所有消费者订阅同一个事件，
  不要让每个控件各自持有/同步副本——这正是本项目两次「不同步」问题的共同成因。
- 自测工具已迁到仓库内 `.tools/uidbg`（已 gitignore）：支持截图 + 模拟滚轮 + 模拟拖拽，
  验证 WinUI 窗口交互时非常有效。注意注入滚轮前要先点击标题栏让窗口取得焦点。

## 第四轮：以本机原版 RPE 为基准对齐操作习惯（提交 7aa634a）

**关键发现**：本机运行着原版 RPE —— 进程名 `!) ChartEditor`（窗口标题 PhiEdit），
目录 `C:/PhigrosFanmadeChartEditor`（只有编译好的 Unity 程序，没有 C# 源码）。
它是用户期望效果的权威参照，可用 `.tools/uidbg` 注入滚轮/点击实测其行为。

**实测结论（在本机原版上注入滚轮验证）**：
- 网格：红色粗横线=整拍线（带拍号）、**绿色横线**=时间细分、黄色竖线=音符 X 网格
- 拍号自上而下递减（31 在上、30 在下）→ 时间自下而上流逝
- **滚轮向下 = 拍号变小**（实测 31 → 30，3 格 ≈ 0.75 拍 = 3×1/4 subdivision）
  → 我此前实现的「向下滚=拍号变大」方向是反的，已翻转
- 判定线（白色粗线）固定在编辑区最下方

**本轮实现**：
- 属性页签合并：音符+事件 → 一个动态页签；无选中=「编辑」且 IsEnabled=false；
  选中音符自动切页签改名「音符」，选中事件改名「事件」
- 横线改绿色（Subdivision/MinorSubdivision → #4AA84E）
- 滚轮统一到 `RootLayout.PointerWheelChanged`（冒泡）统一处理：
  画布不再自己处理滚轮；指针在编辑区内即滚动，与焦点控件无关
  ⚠ WinUI3 **未公开** `PointerWheelChangedEvent` 路由事件，无法用 AddHandler(handledEventsToo)
- 滚轮方向翻转 + 一格 = 1/division 拍（新增 `EditViewport.ScrollByBeats`）
- 窗口 16:9 锁定：AppWindow.Changed 中按变化更明显的边回推另一条边；
  编辑区列宽改用 `GridUnitType.Star`，窗口变窄时两区等比收缩不被遮挡
- 编辑区功能：Ctrl 多选、Shift 框选（两区都有）、整组拖动、复制/剪切/粘贴/镜像/全选
  （底栏 6 个按钮 + 快捷键 Ctrl+C/X/V/M/A）

**重要教训**：`UndoStack.Push(action)` 内部会执行一次 `action.Redo()`，
所以约定必须是「Redo = 操作后的状态、Undo = 操作前的状态」，
Push 之后**不能**再手动执行一次操作，否则会重复应用（粘贴/删除曾因此出错）。
